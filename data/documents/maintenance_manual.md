# Machine Maintenance Manual

**Document type:** Reference manual
**Applies to:** All production and assembly line machinery
**Owner:** Plant Maintenance Department

## Purpose

This manual describes the maintenance program for production machinery across
all lines, including maintenance categories, scheduling, downtime
investigation, and documentation requirements. It is the primary reference
for maintenance technicians, line supervisors, and reliability engineers.

## Maintenance Categories

The plant uses three categories of maintenance activity:

- **Preventive maintenance (PM):** Scheduled, time-based or usage-based
  servicing performed before a failure occurs (lubrication, belt tension
  checks, filter changes, calibration, cleaning). PM intervals are set per
  machine type based on manufacturer recommendations and historical failure
  data.
- **Inspection:** A scheduled or triggered check of machine condition
  (temperature, vibration, noise, visual wear) that does not itself involve
  repair work. Inspections may result in a finding that is "flagged for
  monitoring" (no immediate action, re-check on the next cycle) or
  "flagged for corrective action" (schedule a repair before the next
  scheduled PM).
- **Corrective maintenance:** Unscheduled repair work performed in response
  to a detected or reported failure. Corrective work should always record a
  `failure_type` category and a plain-language description of what was
  found and what was done.

## Preventive Maintenance Scheduling

- Every machine has a PM interval defined by its machine type (see the
  equipment register for current intervals).
- PM work orders are auto-generated by the maintenance scheduling system and
  must be closed out with a technician signature and downtime record, even
  when downtime is zero.
- A missed PM (not completed within its scheduled window) must be escalated
  to the shift supervisor and rescheduled within 48 hours.
- PM does not eliminate the need for inspection-driven corrective action:
  a machine can pass its most recent PM and still develop a fault before the
  next one is due.

## Downtime Investigation Checklist

When a machine has unplanned downtime, the investigating technician or
engineer should work through the following, in order:

1. **Confirm the timeline.** When did the downtime start, and on which
   shift? Was it a single continuous stoppage or several shorter ones?
2. **Check the maintenance log for that machine.** Has this machine had any
   inspection or corrective events in the recent past, and if so, what
   category and failure type were recorded?
3. **Check for a pattern, not just a single event.** A single isolated fault
   is treated differently from a machine with multiple similar
   `failure_type` entries in its history - repeated instances of the same
   failure type are a signal of a developing or worsening condition, not a
   one-off.
4. **Cross-reference production data for the same date/shift/machine**, if
   available, to see whether the downtime lines up with a drop in actual
   output relative to planned output.
5. **Cross-reference quality data for the same date/shift/machine**, if
   available. A machine experiencing mechanical degradation often produces
   a higher defect rate before it fully stops, not just downtime after it
   stops.
6. **Document findings in the maintenance record**, including what was
   inspected, what was found, what corrective action was taken (if any),
   and the technician who performed the work.

## Common Failure Modes by Machine Type

| Machine type | Common failure modes |
|---|---|
| CNC Press | Hydraulic leaks, calibration drift, tooling wear |
| Robotic Welder | Electrical faults, sensor faults, alignment drift |
| Paint Robot | Nozzle clogging, sensor faults, calibration drift |
| Conveyor Assembler | Motor failures, belt wear, conveyor jams, sensor faults |
| Case Packer | Jams, sensor faults, belt wear |

Motor-related failures are covered in detail in the **Motor Failure SOP**
(`motor_failure_sop.md`) and should always be cross-referenced when a
Conveyor Assembler or any motor-driven machine shows repeated downtime.

## Escalation

- Any single downtime event exceeding 60 minutes must be reported to the
  shift supervisor within the shift.
- Any machine with three or more corrective maintenance events of the same
  `failure_type` within a 90-day window must be escalated to the
  Reliability Engineer for a root-cause review and a decision on whether to
  replace (not just repair) the affected component.
- Recurring failures should not be closed out with "repaired and resumed
  operation" alone - the escalation review should consider whether the
  repair addressed the underlying condition or only the symptom.

## Documentation Requirements

Every maintenance event, whether preventive, inspection, or corrective, must
record: date, machine, event type, failure type (if applicable), a
plain-language description, downtime minutes, the technician who performed
the work, and status (Resolved / In Progress / Scheduled). Vague
descriptions ("fixed it", "checked machine") are not acceptable -
descriptions should state what was observed and what was done.
